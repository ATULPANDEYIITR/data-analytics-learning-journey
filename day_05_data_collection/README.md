# Data Collection: Beginner to Advanced

## 1. Introduction

Data collection is the systematic process of obtaining observations, measurements, records, responses, or events for a defined purpose. It is the foundation of empirical research, business analytics, operational monitoring, experimentation, statistical inference, and data-driven decision-making.

A collection process is not merely the act of gathering a large quantity of information. A useful collection system must answer several questions:

- What information is required?
- Who or what is the target population?
- What is the unit of observation?
- Where will the data come from?
- How will observations be selected?
- How will measurements be made?
- How will missing, invalid, duplicated, or contradictory records be handled?
- How will provenance be preserved?
- How will privacy and security be maintained?
- How will collection quality be monitored?
- How will the process behave when the source fails or changes?

The accompanying Python script demonstrates these principles through executable examples.

## 2. Fundamental Terminology

### Data

Data consists of recorded observations, measurements, events, responses, or other representations of phenomena.

### Dataset

A dataset is an organized collection of observations. The script represents a dataset using `Dataset` and `Observation` classes.

### Observation

An observation is one unit of recorded information. Depending on the application, it may represent:

- a customer response
- a purchase
- a temperature reading
- a login event
- a machine measurement
- an API record

### Variable

A variable is a characteristic recorded for an observation, such as age, price, country, transaction amount, or satisfaction.

### Population

The population is the complete group about which a study intends to make statements.

### Sample

A sample is a subset selected from the population.

### Sampling Frame

A sampling frame is the operational list or mechanism from which sample units can actually be selected. A major distinction is that the sampling frame may not perfectly represent the target population.

### Metadata

Metadata is information describing other data. Examples include:

- source system
- collection timestamp
- schema version
- geographic coverage
- collector version
- measurement unit

### Provenance

Provenance records where data originated, when it was collected, how it was obtained, and which transformations were applied.

## 3. Primary and Secondary Data

### Primary Data

Primary data is collected directly for the current research or operational purpose.

Examples include:

- a newly designed customer survey
- an interview
- a controlled experiment
- a newly deployed sensor
- a specially designed observational study

Primary collection provides control over variables, definitions, measurement procedures, and sampling design.

Its disadvantages can include:

- collection cost
- time requirements
- respondent burden
- nonresponse
- measurement error
- operational complexity

### Secondary Data

Secondary data was previously collected for another purpose and is reused for the current analysis.

Examples include:

- government statistics
- historical transaction records
- existing company databases
- published datasets
- archived logs
- previously conducted surveys

Secondary data can be economical and extensive, but its definitions, population coverage, measurement procedures, time period, and original purpose must be examined before reuse.

A large secondary dataset is not automatically appropriate for a new research question.

## 5. Survey Design

Survey quality begins before respondents answer questions.

A well-designed survey should have:

- a clearly defined target population
- explicit eligibility criteria
- unambiguous questions
- appropriate response categories
- a defined recall period
- consistent terminology
- appropriate handling of missing or inapplicable responses
- pilot testing

### Leading Questions

A leading question encourages a particular response.

For example, asking whether a customer agrees that a service was "excellent" embeds an assumption about the service.

A neutral question should not presuppose the desired answer.

### Double-Barreled Questions

A double-barreled question asks about multiple concepts at once.

For example:

> How satisfied are you with our prices and customer support?

A respondent could like the prices while disliking customer support. The question should therefore separate these concepts.

### Ambiguous Questions

Terms such as "regularly," "often," or "recently" can mean different things to different respondents.

A measurable recall period or explicit frequency scale improves consistency.

### Loaded Questions

A loaded question uses emotionally or normatively charged framing that can influence responses.

## 7. Sampling

Sampling determines which units are included in a study.

### Simple Random Sampling

Simple random sampling gives population units equal selection probabilities under the appropriate design.

The script uses Python's random sampling functionality to demonstrate this method.

Its advantages include conceptual simplicity and strong theoretical properties under appropriate conditions.

### Systematic Sampling

Systematic sampling selects observations using a regular interval after determining an initial position.

It can be operationally convenient, but periodic patterns in the population can cause bias when they align with the sampling interval.

### Stratified Sampling

Stratified sampling divides a population into strata and samples within each stratum.

Examples of strata include:

- customer segment
- geographic region
- age group
- organization size

Stratification can improve representation of important subgroups and can improve statistical efficiency when strata are meaningfully related to the outcome.

The script demonstrates approximately proportional allocation.

### Cluster Sampling

Cluster sampling selects groups of units rather than individual units.

Examples include:

- selecting schools and surveying students within them
- selecting geographic areas and surveying households
- selecting branches and collecting records within branches

Cluster sampling can reduce collection cost but may increase sampling variance because units within a cluster can be correlated.

### Reservoir Sampling

When the full population is not available simultaneously, reservoir sampling provides a method for obtaining a fixed-size uniform sample from a stream.

For a sample size of `k`, reservoir sampling requires only `O(k)` additional memory while processing the stream in `O(N)` time.

## 8. Sampling Bias

Sampling bias occurs when the collection design systematically causes some relevant population units to be represented differently from others.

A critical distinction is:

**Random sampling from a biased sampling frame does not remove frame bias.**

For example, if the target population contains both online and offline customers but only online customers can enter the sampling frame, randomly sampling the online frame cannot recover the missing offline population.

The script demonstrates this coverage problem.

---

## 9. Important Forms of Bias

### Coverage Bias

Some members of the target population cannot enter the sampling frame.

### Selection Bias

The probability of inclusion is systematically related to characteristics relevant to the study.

### Nonresponse Bias

Selected units fail to respond, and responders differ systematically from nonresponders.

### Measurement Bias

The measurement procedure systematically produces distorted values.

### Interviewer Bias

The interviewer's behavior influences responses or observations.

### Recall Bias

Participants remember historical events inaccurately or differently.

### Social Desirability Bias

Respondents modify answers to appear socially acceptable.

### Survivorship Bias

Collection focuses on entities that remain visible while excluding entities that disappeared or failed.

### Confirmation Bias

Collection is designed or interpreted in a way that preferentially seeks supporting evidence for an existing belief.

### Instrumentation Bias

Changes in devices or measurement procedures alter recorded values.

## 10. Sample Size

For a simple estimate of a population proportion, an approximate planning equation is:

`n = z² p(1-p) / e²`

where:

- `n` is the approximate sample size
- `z` is the selected confidence critical value
- `p` is the expected population proportion
- `e` is the desired margin of error

The script uses the conservative value `p = 0.5` in one demonstration.

Sample-size planning is not simply a matter of choosing a large number. Real studies can require consideration of:

- population size
- expected variability
- confidence level
- margin of error
- design effect
- stratification
- clustering
- expected nonresponse
- subgroup estimates

The script also demonstrates a finite-population correction.

## 12. Measurement Error

Measurement error is the difference between the recorded value and the underlying value being measured.

The script demonstrates:

- measurement error
- mean error
- mean absolute error

Systematic error can consistently shift measurements in one direction.

Examples include:

- poorly calibrated sensors
- ambiguous survey questions
- inaccurate clocks
- faulty instruments
- inconsistent interviewer procedures

Increasing sample size does not automatically remove systematic measurement error.

## 18. Retries and Exponential Backoff

Transient failures can occur because of:

- temporary network errors
- service overload
- short-lived infrastructure failures
- rate limiting

The script demonstrates bounded retries with exponential backoff.

A basic sequence can increase delays approximately as:

`base_delay × 2^attempt`

Retries should not be applied blindly.

Permanent errors such as invalid credentials or malformed requests generally should not be retried indefinitely.

Retries can also amplify system load if every client retries aggressively at the same time. Production systems may therefore use bounded retries and jitter.

## 25. Idempotency

In distributed systems, the same logical event may be delivered more than once.

An idempotent collector ensures that repeated delivery does not repeatedly create the same logical effect.

The script implements a simple identifier-based collector.

For example, if event `E1` is received twice, the first occurrence is accepted and the second is recognized as a duplicate.

Production systems may implement idempotency using:

- database uniqueness constraints
- durable event IDs
- idempotency keys
- transactional writes
- deduplication stores

## 26. Event Time and Processing Time

These concepts are distinct.

### Event Time

The time when the underlying event occurred.

### Processing Time

The time when the collection or processing system handled the event.

They can differ because of:

- network latency
- buffering
- retries
- offline devices
- queue delays
- batch processing

This distinction becomes important in streaming and time-series collection.

## 27. Batch vs Streaming Collection

### Batch Collection

Batch systems process groups of records periodically.

Examples:

- daily transaction imports
- monthly survey files
- scheduled database exports

Advantages:

- simpler architecture
- easier operational management

Limitations:

- higher latency

- large periodic workloads

### Streaming Collection

Streaming systems process events continuously.

Examples:

- IoT telemetry
- application events
- security events
- real-time transaction monitoring

Advantages:

- low latency
- continuous visibility

Limitations:

- greater architectural complexity
- ordering issues
- duplicate delivery
- backpressure
- checkpointing
- fault recovery

## 28. Delivery Semantics

The script distinguishes three concepts.

### At-Most-Once

An event is processed zero or one time.

Possible consequence:

- data loss

### At-Least-Once

The system retries until successful delivery or acknowledgement.

Possible consequence:

- duplicate events

### Exactly-Once

The system provides semantics intended to make each logical event's effect occur once.

Exactly-once behavior is difficult in distributed systems and usually depends on coordinated transactional or idempotent mechanisms. It should not be assumed merely because a system retries successfully.

Checkpoint design must consider:

- consistency

## 36. Backpressure

Backpressure occurs when the producer generates data faster than consumers can process it.

Without controls, queues can grow until memory or storage resources are exhausted.

Possible responses include:

- slowing the producer
- bounding queues
- buffering
- scaling consumers
- rejecting excess traffic
- prioritizing important events
- applying flow control

Backpressure is particularly important in streaming systems.

## 46. Important Distinctions

### Large Dataset vs Representative Dataset

A dataset can contain millions of records and still be biased.

Sample size addresses random uncertainty, while collection design determines whether systematic selection problems exist.

### Missing vs Zero

A missing value means the value was not observed or recorded.

Zero is an observed value equal to zero.

They should not be substituted without justification.

### Validation vs Accuracy

Validation checks whether a value conforms to rules.

Accuracy asks whether it correctly represents reality.

A record can pass validation and still be inaccurate.

### Random Sampling vs Randomized Experiment

Random sampling concerns how observations are selected from a population.

Random assignment concerns how experimental subjects are assigned to conditions.

They solve different problems.

### Event Time vs Processing Time

Event time represents when an event occurred.

Processing time represents when the system processed it.

### Pseudonymization vs Anonymization

Pseudonymization replaces identifiers.

Anonymization seeks to prevent identification under a specified threat model.

### Data Collection vs Data Analysis

Collection obtains observations.

Analysis interprets those observations.

Poor collection can undermine otherwise sophisticated analysis.

## 52. Conceptual Model

The most important conceptual relationship is:

`Purpose → Population → Sampling Frame → Sample → Measurement → Collection → Validation → Storage → Quality Monitoring`

Each stage can introduce error.

For example:

- an incorrect population definition creates conceptual error
- an incomplete sampling frame creates coverage bias
- poor sampling creates selection problems
- poor questions create measurement bias
- missing responses create nonresponse bias
- faulty sensors create measurement error
- failed ingestion creates missing records
- duplicate retries create duplication
- schema changes create structural inconsistency
- weak security creates privacy and integrity risks

A high-quality dataset therefore depends on the entire collection process rather than only the final number of records.
